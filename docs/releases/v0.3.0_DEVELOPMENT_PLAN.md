# Resolutive Science v0.3.0 — Development Plan

**Status:** `v0.3-dev`  
**Primary objective:** strong falsification of the frozen RCMS screening surrogate  
**RSMS compatibility baseline:** `RSMS-1.0-rc.1`  
**Parent scientific release:** `v0.2.0` — DOI `10.5281/zenodo.22002018`

## 1. Scientific principle

v0.3.0 is not a search for additional favorable fits. It is a falsification release.

The frozen screening surrogate inherited from v0.2.0 is:

\[
H_{\mathrm{eff}}^2(z)=H_{\Lambda\mathrm{CDM}}^2(z)+H_0^2A_R\ln(1+z).
\]

The v0.3 development line must not change this equation in response to unfavorable results. A failure to survive the preregistered tests is itself a publishable scientific result.

## 2. Release questions

v0.3.0 must answer, as directly as possible:

1. Does the recurring positive direction survive null-data false-positive tests?
2. Can the pipeline recover injected amplitudes without systematic bias?
3. Is the positive direction distributed across datasets or dominated by one family?
4. Does the logarithmic deformation outperform equally complex one-parameter controls?
5. Is the apparent amplitude near `A_R ~ 0.21` stable across independent subsets?
6. Does the model retain any advantage after complexity penalties?
7. Can a prediction be frozen before inspecting an independent target outcome?

## 3. Planned protocol sequence

### P09 — Null false-positive calibration

Generate synthetic observations under the null model with `A_R = 0`, preserving realistic sampling/covariance where possible. Run the frozen RCMS inference pipeline unchanged.

Primary outputs:

- false-positive rate for `A_R > 0`;
- bias of the recovered amplitude under the null;
- empirical distribution of the test statistic;
- comparison to nominal confidence intervals.

No observational RCMS result may be used to tune the null generator after P09 freeze.

### P10 — Injection/recovery calibration

Inject preregistered amplitudes spanning negative, zero, and positive values and test recovery.

Required metrics:

- amplitude bias;
- coverage;
- sign recovery probability;
- uncertainty calibration;
- failure regions.

### P11 — Equal-complexity functional controls

Compare the logarithmic RCMS term against preregistered one-parameter alternatives using the same nuisance structure and data.

Candidate control families must be fixed before outcome inspection. The purpose is to test whether the logarithmic form carries discriminating information beyond a generic smooth one-parameter deformation.

### P12 — Leave-one-dataset-out stress test

Repeat the cumulative synthesis while removing one dataset family at a time.

Primary question:

> Does the positive direction survive without any single dataset family?

This protocol must preserve negative leave-one-out outcomes.

### P13 — Systematics and nuisance sensitivity

Vary only preregistered, scientifically defensible analysis choices such as selected covariance treatments, nuisance assumptions, and cuts.

The protocol must report the full sensitivity map rather than only the most favorable branch.

### P14 — Amplitude stability test

Test whether the effective amplitude is compatible with a stable value across independent redshift ranges and observational families.

The v0.2.0 descriptive scale near `A_R ~ 0.21` is treated as a target to falsify, not a value to enforce.

### P15 — Complexity-penalized model comparison

Evaluate RCMS and control models with metrics appropriate to the available likelihood structure, including AIC/BIC and, only where justified and reproducible, Bayesian evidence or posterior model comparison.

A positive best-fit amplitude alone is not sufficient for model preference.

### P16 — Preregistered out-of-sample prediction

Freeze a quantitative prediction, uncertainty interval, decision criterion, code commit, and target dataset/observable before inspecting the target result.

This is the highest-value gate planned for v0.3.0.

## 4. Non-negotiable falsification rules

- No changing the logarithmic surrogate to rescue a failed test.
- No post-hoc threshold changes after result inspection.
- No deleting negative or null results.
- No combining statistically overlapping evidence as if independent.
- No promotion of `resolutiva-reformulacao` hypotheses into the v0.3 RCMS evidence line without a separate compatibility and falsification process.
- No discovery language based only on repeated positive best fits.

## 5. Control-model design principles

All alternative deformation controls should, where possible:

- use the same number of additional free parameters as RCMS;
- share the same nuisance-parameter treatment;
- use identical datasets and covariance structures;
- be normalized in a preregistered manner to avoid unfair scale advantages;
- be evaluated by identical scoring and residual diagnostics.

## 6. Reproducibility requirements

Each protocol must include, as applicable:

- preregistration document;
- immutable input manifest;
- source URLs and dataset licenses;
- checksums/hashes;
- runner script;
- fixed seeds for synthetic work;
- environment/dependency record;
- machine-readable output;
- frozen Markdown scientific interpretation;
- known limitations;
- GitHub Actions workflow where computationally practical.

## 7. Publication criterion

v0.3.0 becomes a publication candidate only when the falsification suite is complete enough to answer whether the v0.2 RCMS pattern survives deliberate adversarial testing.

Publication does not require a positive outcome.

A scientifically meaningful negative result is sufficient if it is preregistered, reproducible, documented, and preserved.

## 8. Maturity path

`v0.3-dev` -> experimental protocols -> frozen protocol outcomes -> release audit -> `v0.3.0-rc.1` if needed -> `v0.3.0`

When all required gates are met, development must stop for the explicit publication-candidate declaration before tagging.
