# v0.5 T41 — Higher-Order Matched Tree Null Protocol

**Status:** FROZEN BEFORE EXECUTION  
**Parent:** T40. **New dynamics:** none.

## 1. Question

Do the stable T38 high-radius departures M3 and M7 remain unusual after matching not only

- N;
- tree class;
- exact labeled-node degree sequence;

but also the T39/T40 higher-order topology family

```text

```

M3 and M7 are held out from null generation.

## 2. Baseline standardization

For each of the 9 frozen T25 parents, first reconstruct the exact 99-tree T38 baseline null ensemble.

Use that ensemble only to freeze the null means and standard deviations required to compute C, A and G exactly as in T40.

No M3/M7 value enters this standardization.

## 3. Degree-preserving state space

Encode each tree by its Prüfer sequence.

For a fixed labeled degree sequence, the Prüfer multiset is fixed because label i occurs exactly

```text
degree(i) - 1
```

times.

A proposal consists only of swapping two uniformly selected Prüfer-sequence positions.

Therefore every proposal preserves:

- N;
- labeled degree sequence;
- tree class.

## 4. Frozen higher-order matching box

For each candidate tree compute C,A,G using the T40 baseline-null standardization.

A tree is inside the parent higher-order matching box iff

```text
|C - C_parent| <= 0.50
|A - A_parent| <= 0.50
|G - G_parent| <= 0.50.
```

The tolerance 0.50 is frozen before execution and is measured in baseline-null standard-deviation units.

No M3/M7 condition is allowed.

## 5. Constrained random-transposition walk

Start from the exact parent Prüfer sequence.

At each proposal:

1. choose two different sequence positions uniformly;
2. swap them;
3. decode the proposed tree;
4. compute C,A,G;
5. accept the proposal iff the proposed tree remains inside the frozen matching box;
6. otherwise retain the current state.

The walk therefore samples alternative degree-preserving tree arrangements near the parent's higher-order topology region.

## 6. Burn-in, thinning and proposal budget

Frozen schedule per parent:

```text
burn-in accepted moves = 500
thinning accepted moves = 50
requested stored nulls = 99
maximum proposals = 250000.
```

Only accepted moves count toward burn-in/thinning.

## 7. Diversity guard

A stored matched null must satisfy all of:

1. its undirected edge set differs from the parent;
2. at most 90% of the parent's edges are retained;
3. its edge set has not already been stored for that parent.

The 90% overlap ceiling is frozen before execution.

If 99 unique nulls cannot be obtained within the proposal budget, the parent fails the feasibility gate.

No tolerance, thinning, overlap ceiling or proposal budget may be changed after inspecting M3/M7.

## 8. Held-out responses

Only after the 99 matched nulls are frozen for a parent, compute:

```text

M7 = mean existing-edge D_J at R=8.
```

These are never used by the sampler.

For each response report:

- parent value;
- matched-null mean;
- matched-null standard deviation;
- q025;
- median;
- q975;
- parent percentile.
