# v0.5 T60 — Device-Only Stochastic Switching Characterization Protocol

**Status:** PRE-REGISTERED ANALYSIS ARCHITECTURE / HARDWARE ID AND PULSE VALUES PENDING  
**Parent:** T59.  
**Purpose:** establish whether one physically real, individually addressable memristive device can support a conventional stochastic hazard model before any relational q contrast is introduced.

## 1. Scientific boundary

T60 contains **no q manipulation, no relational-network comparison and no lambda_R estimation**.

Its only question is:

> Does a selected physical device, under a fixed current-limited drive and explicit reset/conditioning policy, exhibit repeatable stochastic switching statistics that can be characterized by an ordinary device-only model?

A PASS is a prerequisite for T53/T56. It is not evidence for Resolutive physics.

## 2. Hardware freeze prerequisite

Before a physical run, create an immutable hardware manifest containing:

- manufacturer and exact device type;
- package/array position and device identifier;
- data-sheet revision;
- manufacturer current/voltage limits;
- series/compliance element;
- pulse source and measurement instruments;
- ambient-temperature sensor/instrument;
- wiring schematic;
- firmware/software commit used for pulse generation and acquisition.

No physical T60 confirmation may start while any of these remain unspecified.

Commercial Ag-ion SDC hardware is the accessible candidate class from T59, but any equivalent individually addressable ion-conduction device may be substituted only by a new frozen hardware-specific appendix.

## 3. Event definition

Before the pilot, define a conductance/current threshold that marks switching.

For a pulse beginning at t=0, an event is the first threshold crossing within the applied pulse.

Record:

- EVENT with first-crossing latency t_switch;
- CENSORED if no event occurs before pulse end;
- INVALID only for a predeclared instrumentation/reset fault.

The threshold may not be changed after examining confirmation data.

## 4. Reset / baseline-state gate

Every trial starts from a declared baseline resistance/conductance window measured at a low read voltage that is not expected to materially alter state.

If a nonvolatile device requires an explicit reverse/reset pulse:

1. apply the frozen reset sequence;
2. wait the frozen rest interval;
3. read baseline state;
4. proceed only if state lies within the predeclared baseline window.

A failed reset is logged. It is not silently repeated until a favorable trial appears.

Reset success fraction and state drift are primary device-quality diagnostics.

## 5. Stage P — pilot only

The pilot may determine a useful safe operating regime because no relational hypothesis is tested here.

Use manufacturer-rated current limiting at all times.

The pilot scans a small predeclared monotone pulse-amplitude grid and/or pulse-width grid to identify a regime where:

- events are neither almost never nor almost always observed;
- the device can be reset/conditioned reproducibly;
- switching latency is resolvable by the acquisition system;
- no progressive irreversible drift is apparent;
- voltage/current remain within device limits.

Target an event probability between approximately 0.2 and 0.8 for the base confirmation pulse duration.

Pilot observations are permanently excluded from T60 confirmation statistics and all later T53 confirmation cohorts.

At the end of Stage P freeze:
- drive amplitude V_star;
- base pulse duration tau;
- read voltage;
- reset waveform;
- compliance/current limit;
- rest interval;
- event threshold;
- baseline-state window.

## 6. Stage C — device-only confirmation

Use at least three pulse durations with the same frozen amplitude:

tau, 2*tau, 4*tau.

For each duration acquire equal-size blocks with randomized duration order.

Minimum planned confirmation size:
- 100 valid attempts per duration per device;
- at least 3 independently identified devices if hardware availability permits.

If fewer than 3 devices are available, T60 may characterize repeatability of the available hardware but may not claim device-class generality.

All valid/censored trials are retained.

## 7. Conventional survival / hazard model

For a fixed device condition, let T be switching latency.

The simplest comparator is a stationary memoryless hazard k0:

S(t)=Pr(T>t)=exp(-k0 t).

For fixed-duration binary switching,

p(t)=1-exp(-k0 t).

The three-duration shape therefore predicts

-ln[1-p(tau)]/tau
=
-ln[1-p(2tau)]/(2tau)
=
-ln[1-p(4tau)]/(4tau)
=
k0.

This is ordinary stochastic-process modeling, not a Resolutive prediction.

T60 does not force an exponential model if the data reject it. A rejection means the device requires a different conventional model before T53 can proceed.

No alternative model may be fitted and then used as if preregistered in the same confirmation cohort.

## 8. Stationarity and carryover gates

Partition each duration into chronological blocks.

Record for every trial:
- device ID;
- trial index and timestamp;
- pulse duration;
- measured pulse amplitude;
- baseline state;
- reset result;
- event/censor status;
- switching latency if event;
- ambient temperature;
- peak/current-compliance information.

Predeclared diagnostics:
- event probability by chronological block;
- baseline-state drift by block;
- latency distribution by block;
- dependence on immediately preceding event/reset outcome;
- temperature association.

A monotone drift, strong carryover or reset-conditioned bifurcation means a single stationary k0 is inadequate.

## 9. Acceptance hierarchy

### T60-A — physical stochasticity

PASS if repeated nominally identical attempts produce both EVENT and CENSORED outcomes or materially variable event latency beyond measurement resolution, while instrumentation and reset controls pass.

This only establishes stochastic/variable device behavior.

### T60-B — repeatability

PASS if reset success and baseline-state distributions remain within the hardware-specific frozen limits, without progressive destructive drift.

### T60-C — simple stationary-hazard adequacy

PASS only if the frozen exponential-hazard comparator describes the held-out duration dependence and chronological blocks within a predeclared uncertainty/fit gate to be numerically specified in the hardware-specific appendix after Stage P and before Stage C.

If T60-C fails but T60-A/B pass, freeze a **new** conventional model protocol before further data. Do not proceed directly to q tests.

### T60-D — device-class reproducibility

PASS only with independent devices showing compatible model form under their own independently measured parameters.

## 10. What cannot count as a positive result

The following are ordinary device behavior, not Resolutive evidence:

- stochastic threshold variation;
- stochastic switching latency;
- voltage-dependent switching probability;
- temperature-dependent switching probability;
- device-to-device variation;
- history/carryover;
- successful fit of a conventional stochastic model.

The physical q experiment starts only after this conventional behavior is understood well enough to define k0 independently.

## 11. Safety / hardware limit

Use only manufacturer-rated low-voltage/current-limited operation. A higher current or voltage may permanently alter filamentary devices and invalidate stationarity.

No attempt to increase signal by exceeding manufacturer ratings is part of T60.
