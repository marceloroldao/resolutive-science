## 1. Question

Given composable Resolutive Transitions

```text
[R_A] --T_AB--> [R_B] --T_BC--> [R_C],
```

what can be inferred about their composition without assuming dynamics, time, energy, action, metric, or path independence?

## 2. Composition as trajectory construction

The ordered pair of transitions defines a composed Resolutive Trajectory:

```text
Gamma_ABC = T_BC o T_AB.
```

Its source and target are

```text
source(Gamma_ABC) = [R_A]
target(Gamma_ABC) = [R_C].
```

This construction requires only source-target compatibility.

## 3. Direct transition is not the composed trajectory

A direct transition may also exist:

```text
T_AC : [R_A] -> [R_C].
```

Endpoint equality alone does not imply

```text
T_AC = T_BC o T_AB.
```

Therefore the minimal ontology distinguishes:

- endpoint pair;
- direct transition;
- composed trajectory.

Classification:

```text
SAME_ENDPOINTS != SAME_TRANSITION != SAME_TRAJECTORY
```

unless a later equivalence principle identifies them.

## 4. Associativity

For a longer chain

```text
A -> B -> C -> D
```

a trajectory represented as ordinary ordered composition should satisfy

```text
T_CD o (T_BC o T_AB)
=
(T_CD o T_BC) o T_AB
```

if parentheses merely encode bookkeeping of the same ordered chain.

Thus associativity is adopted for **trajectory concatenation**, not as a new physical law.

```text
TRAJECTORY_COMPOSITION_ASSOCIATIVE = DEFINED
```

This does not imply commutativity.

## 5. Non-commutativity of ordering

In general,

```text
T_BC o T_AB
```

cannot be exchanged with another ordering because source/target domains may not even match.

Hence ordered composition carries structural information.

This is not yet quantum non-commutativity, causal ordering, or a time arrow.

## 6. Endpoint projection

Define an endpoint projection

```text
pi_end(Gamma) = (source(Gamma), target(Gamma)).
```

Many distinct trajectories may share the same endpoint projection:

```text
pi_end(Gamma_1) = pi_end(Gamma_2)
```

while

```text
Gamma_1 != Gamma_2.
```

This formalizes the earlier R2 observation that returning to the same state does not force trajectory triviality.

## 7. Resolutive trajectory equivalence

Introduce only an abstract placeholder equivalence

```text
Gamma_1 ~_Gamma Gamma_2
```

for trajectories that a future physical rule may identify.

No rule for `~_Gamma` is selected at R4.

Possible future criteria could involve observable indistinguishability, homotopy, action, accumulated phase, coherence, or another invariant, but none is imported now.

Status:

```text
TRAJECTORY_EQUIVALENCE = RESERVED / UNDERDETERMINED
```

## 8. Closed Resolutive Trajectory

A trajectory is structurally closed when

```text
source(Gamma) ==_phys target(Gamma).
```

Denote

```text
Gamma_loop : [R] -> [R].
```

A closed trajectory is not automatically the identity transition:

```text
Gamma_loop != I_[R]
```

in general.

This distinction leaves open the possibility of a future path-sensitive invariant without asserting that one exists.

## 9. Conventional comparator

The resulting structure is category/path-like mathematics and is conventional at this level.

```text
R4_NOVELTY = CONVENTIONAL_STRUCTURAL_FOUNDATION
```

## 10. Constraint propagated forward

A future relational physical quantity must declare whether it is:

```text
ENDPOINT_ONLY:       Q = Q([R_A],[R_B])
TRANSITION_DEPENDENT: Q = Q(T_AB)
TRAJECTORY_DEPENDENT: Q = Q(Gamma)
```

These are inequivalent model classes.

In particular, a future Resolutive Energy definition must not silently switch between endpoint difference and trajectory quantity.
